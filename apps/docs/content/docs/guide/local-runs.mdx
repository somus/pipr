---
title: "Local runs"
description: "Run Pipr review tasks against local git changes without publishing comments."
---

Local review executes configured change-request tasks against git state and prints the result. Use it while tuning config or prompts, before enabling hosted publication.

## Review working-tree changes

Choose an explicit comparison base:

```bash
git fetch origin main
pipr review --base origin/main
```

Without `--head`, Pipr reviews committed changes after the merge base plus staged and unstaged edits to tracked files.

## Review committed refs

Set `--head` for a strict ref-to-ref comparison:

```bash
pipr review --base origin/main --head feature/review-policy
```

Use `--config-dir <path>` for a nonstandard config directory.

## Select local tasks

Local review runs each unique task registered through `pipr.on.changeRequest(...)`. It ignores hosted action filters and skips tasks declared with `local: false`.

Use `ctx.run.trigger === "local"` when a task should run in both environments but render different output.

## Read local output

Pipr writes progress to stderr and final review output to stdout. Normal output is Markdown followed by local inline findings.

Use JSON when another tool consumes the result:

```bash
pipr review --base origin/main --json
```

The top-level `formatVersion` is currently `2`. Check it before reading other fields. Local results include public comments, findings, dropped findings, task checks, repair status, and a bounded run summary; publication is disabled.

## Model authentication

Models with `apiKey` read the declared secret from the local process environment. Bun also loads standard environment files from the working directory.

Models without `apiKey` use Pi authentication from:

1. `--pi-agent-dir`
2. `PI_CODING_AGENT_DIR`
3. `$HOME/.pi/agent`

Pipr still uses the provider and model declared in config. Hosted runs do not receive this local directory, so select an environment-backed model outside local runs.

## Trust local config

Local review loads `.pipr/config.ts` from the current workspace. Run it only on branches whose config and task code you trust, because that code can access exported environment values.

Before spending model quota:

```bash
pipr check --require-env
pipr inspect
```

## Capture diagnostics

Capture a local run when you need timing, retry, tool, validation, or output evidence:

```bash
pipr review --base origin/main --trace
```

Pass a path to `--trace` to choose the store. See [Debug captured runs](/docs/guide/run-observability) for inspection and security guidance.

## Local and hosted differences

| Behavior | Local | Hosted |
| --- | --- | --- |
| Config source | Current workspace | Base commit |
| Diff source | Working tree or explicit refs | Exact change-request base and head |
| Comments and statuses | Disabled | Enabled when configured |
| Authentication | Environment keys or local Pi auth | Delivery secret store |
| Best use | Config and prompt iteration | Production review |
