title: "Bitbucket"
description: "Run Pipr reviews and commands on Bitbucket Cloud or Data Center."
---

Pipr supports Bitbucket Cloud and Bitbucket Data Center 9.2 or later. Use a trusted webhook worker for Data Center, commands, replies, forks, or Cloud repositories where pull requests cannot safely access credentials.

## Generate the adapter files

Run:

```bash
pipr init --adapters bitbucket
```

This creates `bitbucket.pipr.env.example` and a Cloud `bitbucket-pipelines.yml`. Configure only the environment block for your deployment.

## Use Bitbucket Pipelines

Use the generated pipeline only for trusted same-repository pull requests. Pull request pipelines execute source-controlled YAML, so a contributor who can replace that file can read variables available to the job. Fork pull requests do not trigger the generated pipeline.

Configure these secured repository variables:

- `BITBUCKET_EMAIL`
- `BITBUCKET_API_TOKEN`
- the model-provider key named by `.pipr/config.ts`

The pipeline handles automatic reviews. Use a webhook worker for `@pipr` commands and reply verification.

## Configure a Cloud worker

Cloud uses a review token plus a separate token for effective permission checks:

```bash
export BITBUCKET_WORKSPACE="workspace"
export BITBUCKET_REPO_SLUG="repository"
export BITBUCKET_EMAIL="bot@example.com"
export BITBUCKET_API_TOKEN="..."
export BITBUCKET_PERMISSION_EMAIL="admin@example.com"
export BITBUCKET_PERMISSION_API_TOKEN="..."
export PIPR_WEBHOOK_SECRET="..."
export DEEPSEEK_API_KEY="..."
```

Use a scoped user API token for the Pipr bot with:

- `read:user:bitbucket`
- `read:repository:bitbucket`
- `read:pullrequest:bitbucket`

The permission token must belong to a workspace administrator and needs `read:repository:bitbucket`.

Create repository webhooks for:

- `pullrequest:created`
- `pullrequest:updated`
- `pullrequest:fulfilled`
- `pullrequest:rejected`
- `pullrequest:superseded`
- `pullrequest:comment_created`

Configure the same secret as `PIPR_WEBHOOK_SECRET`.

## Configure a Data Center worker

Data Center uses its HTTPS application root, project key, repository slug, and HTTP access tokens:

```bash
export BITBUCKET_BASE_URL="$BITBUCKET_DATA_CENTER_URL"
export BITBUCKET_PROJECT_KEY="PROJECT"
export BITBUCKET_REPO_SLUG="repository"
export BITBUCKET_TOKEN="..."
export BITBUCKET_USER="pipr-bot"
export BITBUCKET_PERMISSION_TOKEN="..."
export PIPR_WEBHOOK_SECRET="..."
export DEEPSEEK_API_KEY="..."
```

Grant the review token repository read and write access. Command authorization requires a separate system-administrator token that can evaluate effective repository permissions.

Create repository webhooks for:

- `pr:opened`
- `pr:from_ref_updated`
- `pr:modified`
- `pr:merged`
- `pr:declined`
- `pr:deleted`
- `pr:comment:added`

Data Center 9.2 is the minimum supported release for multiline pull request anchors. Thread resolution requires the comment contract available since 8.9.

## Start the worker

Run one worker for one dedicated checkout:

```bash
pipr webhook serve \
  --host bitbucket \
  --repository workspace/repository \
  --workspace /srv/pipr/repository \
  --database /var/lib/pipr/webhooks.sqlite \
  --hostname 127.0.0.1 \
  --port 8787
```

Use [Deploy the webhook runner with Docker](/docs/guide/webhook-docker) for persistent state and certificate setup.

## Supported behavior

Cloud and Data Center support:

- pull request creation, update, and close events
- trusted config and exact-head checkout
- main comments and left-side or right-side multiline findings
- prior-state loading, verifier replies, and thread resolution
- `@pipr` commands with effective repository permissions
- task and aggregate commit statuses
- fork checkout and stale-head rejection

Bitbucket does not document a native suggested-change format, so Pipr renders replacement code in fenced blocks.
