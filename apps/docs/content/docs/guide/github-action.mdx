Use the generated GitHub workflow for automatic reviews, `@pipr` commands, and verifier replies. It runs the pinned Pipr image on GitHub.com or GitHub Enterprise Server (GHES).

## Generate the workflow

Run:

```bash
pipr init --adapters github
```

The generated workflow uses a full checkout, passes the model and GitHub credentials, and uploads a protected run bundle:

```yaml
name: pipr

on:
  pull_request:
    types: [opened, synchronize, reopened, ready_for_review]
  issue_comment:
    types: [created]
  pull_request_review_comment:
    types: [created]

permissions:
  contents: read
  pull-requests: write
  issues: write

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6
        with:
          fetch-depth: 0
      - uses: somus/pipr@v0.6.3 # x-release-please-version
        id: pipr
        env:
          DEEPSEEK_API_KEY: ${{ secrets.DEEPSEEK_API_KEY }}
          GITHUB_TOKEN: ${{ github.token }}
          PIPR_RUN_AGE_RECIPIENTS: ${{ vars.PIPR_RUN_AGE_RECIPIENTS }}
      - name: Upload Pipr run bundle
        if: always() && steps.pipr.outputs.run-bundle-path != ''
        uses: actions/upload-artifact@v6
        with:
          name: ${{ steps.pipr.outputs.run-artifact-name }}
          path: ${{ steps.pipr.outputs.run-bundle-path }}
          retention-days: 14
          if-no-files-found: warn
          include-hidden-files: true
```

The config decides which delivered events start tasks:

| Event | Purpose |
| --- | --- |
| `pull_request` | Automatic review on configured lifecycle actions |
| `issue_comment.created` | `@pipr` commands on pull requests |
| `pull_request_review_comment.created` | Authorized replies to Pipr inline comments |

## Permissions

Grant only the permissions required by enabled features:

| Feature | Permission |
| --- | --- |
| Checkout and diff construction | `contents: read` |
| Main comments and command responses | `issues: write` |
| Inline comments and verifier replies | `pull-requests: write` |
| Task and aggregate checks | `checks: write` |

Native review-thread resolution also requires a credential for which GitHub reports `viewerCanResolve: true`. The workflow token can still publish fixed-finding replies when it cannot resolve the native thread.

To require native resolution, store a suitable user credential as a repository secret:

```yaml
- uses: somus/pipr@v0.6.3 # x-release-please-version
  env:
    DEEPSEEK_API_KEY: ${{ secrets.DEEPSEEK_API_KEY }}
    GITHUB_TOKEN: ${{ secrets.PIPR_GITHUB_TOKEN }}
```

## Trusted config and forks

Pull request runs load `.pipr/config.ts` from the base commit, then review the proposed head. Pull request changes can propose new policy, but they cannot alter the policy reviewing that same change.

GitHub controls secret availability for forks. If a required model secret is unavailable, Pipr stops before model execution. Do not use a workflow that exposes write-capable or model credentials to untrusted pull request code.

## GitHub Enterprise Server

Generate a GHES workflow:

```bash
pipr init --github-enterprise-server
```

This selects a self-hosted Linux runner and a GHES-compatible artifact action. Add `--github-runner <label>` for a custom runner label.

If runners cannot reach public registries, provide internal mirrors:

```bash
pipr init \
  --github-enterprise-server \
  --checkout-action internal-actions/checkout@v6 \
  --runtime-image registry.internal.example/pipr:v0.6.3 # x-release-please-version
```

Keep the mirrored image on the same Pipr release. If the instance uses a private certificate authority, make the certificate available inside the Pipr image as well as on the runner.

## Action outputs

The Action exposes:

| Output | Description |
| --- | --- |
| `main-comment` | Rendered main comment, command response, or command help |
| `result` | Versioned JSON result for review, command, verifier, dry-run, ignored, or failure outcomes |
| `execution-id` | Trace identifier for the process |
| `run-bundle-path` | Protected run-bundle path for upload |
| `run-artifact-name` | Artifact name consumed by `pipr runs` |

Parse `result` only after confirming `formatVersion: 2`, then branch on `kind`. Public results contain bounded run and publication summaries; they exclude raw prompts, diffs, credentials, native comment IDs, and internal state.

See [Debug captured runs](/docs/guide/run-observability) to configure encrypted diagnostics.

## Dry run

Set `PIPR_DRY_RUN=1` to validate event parsing and trusted config without model execution or publication:

```yaml
env:
  PIPR_DRY_RUN: "1"
```

For local event fixtures, run `pipr dry-run --host github --event <path>`. Use [Local runs](/docs/guide/local-runs) for normal pre-push review.
