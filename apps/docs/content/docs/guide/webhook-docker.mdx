---
title: "Deploy the webhook runner with Docker"
description: "Run a persistent Pipr webhook worker with Docker Compose."
---

Deploy one webhook worker per repository. The worker uses a dedicated checkout, persists delivery state, listens behind an HTTPS reverse proxy, and finishes active review work during graceful shutdown.

## Prerequisites

You need:

- Docker Engine with Compose v2
- a Linux host that can reach the code host and model provider
- one repository checkout containing `.pipr/config.ts`
- provider credentials from the matching [code-host guide](/docs/guide#start-with-your-code-host)
- an HTTPS reverse proxy to `127.0.0.1:8787`

Do not share one checkout across workers or scale one repository across replicas.

## 1. Create deployment directories

Create separate directories for config, the checkout, and state:

```bash
sudo mkdir -p /srv/pipr/deployment /srv/pipr/repository /srv/pipr/state
```

Keep the checkout and state writable by the container user.

## 2. Download one release

Download `compose.yml` and the environment template from the same Pipr release tag:

```bash
PIPR_VERSION=v0.6.3 # x-release-please-version
curl -fsSL \
  "https://raw.githubusercontent.com/somus/pipr/${PIPR_VERSION}/deploy/webhook/compose.yml" \
  -o /srv/pipr/deployment/compose.yml
curl -fsSL \
  "https://raw.githubusercontent.com/somus/pipr/${PIPR_VERSION}/deploy/webhook/.env.example" \
  -o /srv/pipr/deployment/.env
```

The Compose file pins the matching image. If you use an internal registry, mirror the same release and set `PIPR_IMAGE` in `.env`.

## 3. Prepare the checkout

Clone the repository into `/srv/pipr/repository` and confirm its default branch contains `.pipr/config.ts`. The worker loads policy from the change request base, then checks out the proposed head for review.

## 4. Configure the environment

Open `/srv/pipr/deployment/.env` and set:

- `PIPR_CODE_HOST`
- `PIPR_REPOSITORY`
- `PIPR_WEBHOOK_SECRET`
- the model-provider key named by `.pipr/config.ts`
- the provider values from its guide

Keep `PIPR_BIND_ADDRESS=127.0.0.1` unless a private network supplies the TLS and access boundary. Do not commit `.env` or place secrets in Compose command arguments.

For a private certificate authority, mount its PEM bundle and set `NODE_EXTRA_CA_CERTS` plus `GIT_SSL_CAINFO`. Keep TLS verification enabled.

## 5. Start and verify

From the deployment directory:

```bash
docker compose pull
docker compose up -d
docker compose exec pipr wget -qO- http://127.0.0.1:8787/healthz
```

The health endpoint confirms that the listener accepts deliveries. A real webhook exercises provider and model authentication.

Inspect logs without printing the environment:

```bash
docker compose logs --tail=100 pipr
```

Point the provider webhook at the reverse proxy. Preserve provider headers, restrict the exposed route, and cap request bodies at 2 MiB.

## Operate the worker

Persist `/srv/pipr/state` across restarts and upgrades. Stop gracefully:

```bash
docker compose down
```

Pending deliveries resume after restart. Back up the state directory only while the container is stopped.

To upgrade, download the new release's Compose file, review the changes, then run:

```bash
docker compose pull
docker compose up -d
```
