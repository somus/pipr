Pipr loads repository-owned policy from `.pipr/config.ts`. Start with `pipr.review(...)`; move to custom agents and tasks only when the default review cannot express the workflow.

## Configure a review

This config registers one model, caps inline comments, and runs a general review on change-request updates and `@pipr review`:

```ts twoslash
import { definePipr } from "@usepipr/sdk";

export default definePipr((pipr) => {
  const model = pipr.model({
    provider: "deepseek",
    model: "deepseek-v4-pro",
    apiKey: pipr.secret({ name: "DEEPSEEK_API_KEY" }),
    thinking: "high",
  });

  pipr.config({
    publication: { maxInlineComments: 5 },
  });

  pipr.review({
    id: "review",
    model,
    instructions: {
      findings: "Report concrete correctness, security, and regression risks.",
      summary: "Summarize the change, risk, and useful reviewer focus.",
    },
    entrypoints: {
      changeRequest: ["opened", "updated", "reopened", "ready"],
      command: { pattern: "@pipr review", permission: "write" },
    },
    timeout: "10m",
  });
});
```

Run `pipr check` after editing the config and `pipr inspect` to review the resolved models, tasks, commands, tools, and limits.

## Models and secrets

Model profiles select a Pi provider and model. `pipr.secret(...)` records an environment-variable name; pass the value through the local process, CI secret store, or webhook worker environment.

```ts twoslash
// @include: pipr-builder
const model = pipr.model({
  provider: "deepseek",
  model: "deepseek-v4-pro",
  apiKey: pipr.secret({ name: "DEEPSEEK_API_KEY" }),
});
```

Use an explicit `id` only when multiple profiles use the same provider and model with different credentials or thinking levels. Browse [Pi's Model Catalog](https://pi.dev/models) for current identifiers.

### Use local Pi authentication

For local-only subscription authentication, omit `apiKey` and select that model only when `ctx.run.trigger === "local"`. Hosted runs do not receive your local Pi agent directory, so they must select a profile with an environment-backed key.

See [Local runs](/docs/guide/local-runs#model-authentication) for directory resolution and trust behavior.

## Limit review scope

Use `paths` to restrict changed-code context and publishable inline findings:

```ts twoslash
// @include: pipr-review
pipr.review({
  id: "runtime-review",
  model,
  instructions: reviewInstructions,
  paths: {
    include: ["src/**"],
    exclude: ["**/*.generated.ts", "**/fixtures/**"],
  },
});
```

Path scope does not block read-only access to related repository files. It keeps the manifest and final inline findings focused on matching paths.

## Configure publication

Publication options control visible Pipr output and prior-finding state:

```ts twoslash
// @include: pipr-builder
pipr.config({
  publication: {
    maxInlineComments: 5,
    maxStoredFindings: 50,
    showHeader: true,
    showFooter: true,
    showProgress: true,
    showStats: true,
    autoResolve: {
      userReplies: {
        allowedActors: "author-or-write",
        respondWhenStillValid: true,
      },
    },
  },
});
```

Set `autoResolve: false` to disable verifier-driven replies and thread cleanup. Use `"write"` for `allowedActors` when external contributors must not trigger model calls.

## Limit model calls

Set limits when you need a predictable provider-call budget:

```ts twoslash
// @include: pipr-builder
pipr.config({
  limits: {
    maxAgentRuns: 12,
    diffManifest: {
      maxShards: 4,
    },
  },
});
```

`maxAgentRuns` counts initial calls, large-diff shards, retries, repairs, and fallbacks. `maxShards: 1` disables automatic splitting for review-schema agents.

## Configure fallback and retry

An agent can declare fallback models and retry policy:

```ts twoslash
// @include: pipr-models
const reviewer = pipr.agent({
  name: "reviewer",
  model,
  fallbacks: [backupModel],
  instructions: "Report only actionable defects.",
  output: pipr.schemas.review,
  prompt: () => "Review the current change request.",
  retry: {
    invalidOutput: 1,
    transientFailure: 1,
  },
});
```

Call-level model and fallback options override the agent settings. Without an override, Pipr uses the agent model and fallbacks, then the configured default provider.
