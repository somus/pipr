Triggers select when a task runs. Declare them with `on` on the task itself. The task still decides which agents to call and which final output to emit.

## Configure the default review

`pipr.review(...)` registers change request, command, and local execution around one task. Its `on` defaults to `defaultReviewTriggers`:

```ts twoslash
// @include: pipr-review
pipr.review({
  id: "review",
  model,
  instructions: reviewInstructions,
  on: {
    changeRequest: ["opened", "updated", "reopened", "ready"],
    command: { pattern: "@pipr review", permission: "write" },
  },
});
```

Omit a trigger from `on` to disable it.

## Change-request events

Pipr exposes provider-neutral actions:

```text
opened | updated | reopened | ready | closed
```

Run a custom task for selected actions. `changeRequest: true` uses `opened`, `updated`, `reopened`, and `ready`:

```ts twoslash
// @include: pipr-builder
pipr.task({
  name: "summary",
  on: { changeRequest: ["opened", "updated"] },
  async run(ctx) {
    await ctx.comment("Summary.");
  },
});
```

Use automatic review for work that should run on every relevant update. Use commands for costly or optional workflows.

## Commands

Command patterns must start with `@pipr`:

```ts twoslash
// @include: pipr-builder
pipr.task({
  name: "security",
  on: {
    command: {
      pattern: "@pipr security",
      permission: "write",
      description: "Run the security review.",
    },
  },
  async run(ctx) {
    await ctx.comment("Security review.");
  },
});
```

Named captures parse one argument, while a final rest capture accepts free-form text:

```text
@pipr release-note <version>
@pipr ask <question...>
```

Tasks with input must declare `parse` to map captured arguments into the task input. Use `ctx.command.reply(...)` for a response tied to the source command. Use `ctx.comment(...)` when the task should publish normal review output.

To add a second command to an existing task handle, use `pipr.command(...)`:

```ts twoslash
// @include: pipr-security-task
pipr.command({ pattern: "@pipr sec", permission: "write", task: securityTask });
```

## Command permissions

Permissions use one shared order across code hosts:

```text
read < triage < write < maintain < admin
```

Commands default to `write`. Lower the requirement only when the command cannot expose sensitive context, spend unacceptable provider quota, or publish review findings.

## Local task selection

`pipr review --base <ref>` runs each unique task with a change request trigger, without code-host publication. It ignores the trigger's action list because local git state has no native event action.

Set `local: false` on tasks that must run only in hosted delivery:

```ts twoslash
// @include: pipr-security-agent
pipr.task({
  name: "security",
  on: { changeRequest: true },
  local: false,
  async run(ctx) {
    const diff = await ctx.change.diff({ compressed: true });
    const result = await ctx.pi.run(securityAgent, { diff });
    await ctx.comment({
      main: result.summary.body,
      inlineFindings: result.inlineFindings,
    });
  },
});
```

See [Local runs](/docs/guide/local-runs) for base, head, output, and authentication behavior.
