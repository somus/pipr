---
title: "Entrypoints"
description: "Start Pipr tasks from change requests, commands, or local review."
---

Entrypoints select when a task runs. The task still decides which agents to call and which final output to emit.

## Configure the default review

`pipr.review(...)` can register automatic, command, and local execution around one task:

```ts twoslash
// @include: pipr-review
pipr.review({
  id: "review",
  model,
  instructions: reviewInstructions,
  entrypoints: {
    changeRequest: ["opened", "updated", "reopened", "ready"],
    command: { pattern: "@pipr review", permission: "write" },
  },
});
```

Set either entrypoint to `false` to disable it.

## Change-request events

Pipr exposes provider-neutral actions:

```text
opened | updated | reopened | ready | closed
```

Register a custom task for selected actions:

```ts twoslash
// @include: pipr-task
pipr.on.changeRequest({
  actions: ["opened", "updated"],
  task,
});
```

Use automatic review for work that should run on every relevant update. Use commands for costly or optional workflows.

## Commands

Command patterns must start with `@pipr`:

```ts twoslash
// @include: pipr-security-task
pipr.command({
  pattern: "@pipr security",
  permission: "write",
  description: "Run the security review.",
  task: securityTask,
});
```

Named captures parse one argument, while a final rest capture accepts free-form text:

```text
@pipr release-note <version>
@pipr ask <question...>
```

Use `ctx.command.reply(...)` for a response tied to the source command. Use `ctx.comment(...)` when the task should publish normal review output.

## Command permissions

Permissions use one shared order across code hosts:

```text
read < triage < write < maintain < admin
```

Commands default to `write`. Lower the requirement only when the command cannot expose sensitive context, spend unacceptable provider quota, or publish review findings.

## Local task selection

`pipr review --base <ref>` runs each unique task registered through `pipr.on.changeRequest(...)`, without code-host publication. It ignores hosted action filters because local git state has no native event action.

Set `local: false` on tasks that must run only in hosted delivery:

```ts twoslash
// @include: pipr-security-agent
const securityTask = pipr.task({
  name: "security",
  local: false,
  async run(ctx) {
    const manifest = await ctx.change.diffManifest({ compressed: true });
    const result = await ctx.pi.run(securityAgent, { manifest });
    await ctx.comment({
      main: result.summary.body,
      inlineFindings: result.inlineFindings,
    });
  },
});
```

See [Local runs](/docs/guide/local-runs) for base, head, output, and authentication behavior.
