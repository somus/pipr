---
title: "Debug captured runs"
description: "List, diagnose, and download Pipr run bundles from local storage and GitHub Actions."
---

Pipr captures structured evidence for every hosted review, command, and verifier run. Use `pipr runs` to find slow phases, failed publication calls, invalid-output repairs, dropped findings, and missing evidence without rerunning the model.

GitHub Actions uploads a content-free metadata bundle by default. When age recipients are configured, it also uploads an encrypted diagnostic bundle containing redacted prompts, visible model output, diffs, and validation data. GitHub access discovers the package; only an age identity can decrypt diagnostic content.

Automatic remote discovery and download are GitHub-only. GitLab, Azure DevOps, and Bitbucket reviews still use the same provider-neutral recorder, and trusted webhook or local stores remain available on every host. If custom CI persists a protected package, diagnose it with `pipr runs inspect`.

## List runs for a change request

Pass a pull or merge request number from a repository checkout:

```bash
pipr runs list --pr 42
```

Pass the full provider URL when you are outside a checkout:

```bash
pipr runs list --pr https://github.com/owner/repository/pull/42
```

Pipr merges the selected local store with GitHub Actions records and removes duplicates by execution ID. The `PROTECTION` column reports `plaintext`, `metadata`, `age`, or `unknown` independently from artifact availability. A run can report `available`, `in-progress`, `expired`, `capture-failed`, `upload-failed`, or `indeterminate-missing`.

Pipr attempts anonymous GitHub artifact reads. Set `PIPR_GITHUB_TOKEN` or `GITHUB_TOKEN` with Actions read access when the artifact is not anonymously readable. The token discovers the package but does not decrypt diagnostics.

Use `--host` and `--repository` to override Git remote discovery:

```bash
pipr runs list --pr 42 --host github --repository owner/repository --json
```

Non-GitHub selectors filter local stores only; they never call the provider API.

## Diagnose a run

Generate an X25519 age identity once:

```bash
pipr runs keygen
```

The command prints the public recipient and the identity path, but never prints the secret identity. Configure the recipient in GitHub Actions as `PIPR_RUN_AGE_RECIPIENTS`. Separate multiple recipients with commas or newlines:

```text
PIPR_RUN_AGE_RECIPIENTS=age1team...,age1automation...
```

Keep the identity file private. `pipr runs keygen` writes it with mode `0600` and refuses to overwrite an existing or symlinked path.

Select the latest completed review for a change request:

```bash
pipr runs show --pr 42
```

Select a specific process by its 32-character execution ID:

```bash
pipr runs show 0123456789abcdef0123456789abcdef --timeline
```

The diagnosis is deterministic and does not call an LLM. It reports the critical path, phase durations, retries, repair attempts, time to first token, tool durations, token and cost usage, CPU and memory data, validation drops, publication failures, and missing evidence.

Without a matching identity, an age-protected run still shows its public metadata diagnosis and reports `Diagnostics: locked`. Pass an identity to include the full diagnostic evidence:

```bash
pipr runs show 0123456789abcdef0123456789abcdef \
  --identity ~/.local/state/pipr/keys/run-observability.agekey
```

You can repeat `--identity`. `PIPR_RUN_AGE_IDENTITY` selects a default identity path. An explicitly supplied invalid or non-matching identity is an error.

Use `--json` when another tool or coding agent will consume the diagnosis:

```bash
pipr runs show --pr 42 --json > pipr-diagnosis.json
```

The JSON response includes the manifest, spans, deterministic diagnosis, and artifact descriptors. It never includes prompt or model-output bodies; download the validated bundle when an authorized debugging process needs those files.

## Inspect a manually downloaded artifact

For custom non-GitHub CI, download the protected package from its storage location, then validate and diagnose it locally:

```bash
pipr runs inspect ~/Downloads/pipr-run-artifact.tar.gz
```

Pass the same age identity used by `runs show` to unlock diagnostic evidence:

```bash
pipr runs inspect ~/Downloads/pipr-run-artifact.tar.gz \
  --identity ~/.local/state/pipr/keys/run-observability.agekey \
  --timeline
```

`inspect` accepts ZIP and tar.gz archives or extracted directories. Each input must contain exactly one protected package or plaintext Run Bundle. The command applies the same validation and deterministic diagnosis as provider retrieval. Its `--json` output remains content-free.

## Download a bundle

Download and validate an unpacked bundle:

```bash
pipr runs download 0123456789abcdef0123456789abcdef --output ./pipr-run
```

Metadata-only packages download directly. An age-protected diagnostic requires a matching identity:

```bash
pipr runs download 0123456789abcdef0123456789abcdef \
  --identity ~/.local/state/pipr/keys/run-observability.agekey \
  --output ./pipr-run
```

Outside a repository checkout, provide the provider coordinates explicitly:

```bash
pipr runs download 0123456789abcdef0123456789abcdef \
  --host github \
  --repository owner/repository
```

Add `--archive` to preserve the original GitHub Actions archive beside the validated directory:

```bash
pipr runs download 0123456789abcdef0123456789abcdef \
  --output ./pipr-run \
  --archive
```

Pipr rejects unexpected files, path traversal, symlinks, invalid schemas, artifact hash mismatches, and archives that expand beyond 64 MiB.

## Capture a local review

Local reviews do not capture bundles unless you opt in. Pass a path to control the store:

```bash
pipr review --base origin/main --trace ./.pipr-runs
```

Pass `--trace` without a path to use the platform Pipr state directory, partitioned by repository:

```bash
pipr review --base origin/main --trace
```

The `pipr runs` commands search both `.pipr-runs` and this repository-partitioned platform state directory when neither `--store` nor `PIPR_RUN_STORE_DIR` is set.

Trusted webhook and local captures keep their private plaintext behavior. GitHub Actions chooses encrypted diagnostics only when recipients are configured. Operational flags and environment variables control capture independently from `.pipr/config.ts`:

| Setting | Default | Purpose |
| --- | --- | --- |
| `PIPR_RUN_CAPTURE` | GitHub Actions: `diagnostic` with recipients, otherwise `metadata`; webhooks: `diagnostic` | Set `off`, `metadata`, or `diagnostic`. Diagnostic GitHub capture without recipients publishes metadata only. |
| `PIPR_RUN_AGE_RECIPIENTS` | none | Comma- or newline-separated public X25519 age recipients for GitHub Actions diagnostics. |
| `PIPR_RUN_AGE_IDENTITY` | platform state identity path | Select the local identity used by `runs show`, `runs inspect`, and `runs download`. |
| `PIPR_RUN_STORE_DIR` | `.pipr-runs` in CI; `/var/lib/pipr/runs` for webhooks | Select the filesystem store. |
| `PIPR_RUN_RETENTION_DAYS` | `14` | Set webhook completed-run retention. |
| `PIPR_RUN_MAX_BYTES` | `5368709120` | Set the webhook store quota in bytes. |

Webhook cleanup removes expired runs first, then the oldest completed runs. A capture is protected only while its recorded process is still active, so a hard-killed process cannot leave a permanent quota exemption.

## Export content-free telemetry

Set standard `OTEL_EXPORTER_OTLP_*` and sampling variables to export traces, metrics, and logs over OTLP HTTP/protobuf. Pipr keeps local capture independent from `OTEL_TRACES_SAMPLER`, so disabling trace export does not discard bundle evidence.

OTLP data contains timings, statuses, sizes, hashes, usage, and provider-neutral run metadata. It excludes prompts, model output, source text, stderr snippets, environment values, raw reasoning, and tool payload bodies.

## Update existing CI configuration

Run `pipr init --force --adapters github` only when you intend to regenerate all Pipr-owned starter files. Otherwise, copy the run-artifact step from the current generated GitHub example into the existing workflow.

Existing GitHub workflows without `PIPR_RUN_AGE_RECIPIENTS` automatically publish metadata-only packages. Add the public recipient variable to enable encrypted diagnostics.

The generated GitHub workflow keeps protected packages for 14 days. Pipr does not generate observability artifact wiring or remote retrieval for GitLab, Azure DevOps, or Bitbucket. Teams can add custom protected-package storage and use `pipr runs inspect`, but Pipr does not promise provider-specific discovery or retention behavior for those hosts.

Recipient rotation affects future runs only. Keep old identities for at least the provider retention window if you still need to decrypt existing packages. Share a diagnostic by sharing the validated decrypted directory through an already authorized channel, not by publishing the identity alongside the provider artifact.
