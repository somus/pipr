---
title: "Pipr"
description: "Repository-owned AI review for GitHub, GitLab, Azure DevOps, Bitbucket, Gitea, Forgejo, and Codeberg."
---

Pipr runs repository-owned AI review policy from `.pipr/config.ts`. It builds the changed-code context, runs Pi, validates findings, and publishes through your code host.

## Choose a setup path

Start with the guide for your code host. The same TypeScript review config works across providers.

| Code host | Setup |
| --- | --- |
| GitHub.com or GitHub Enterprise Server | [GitHub quickstart](/docs/guide/quickstart) |
| GitLab.com or GitLab Self-Managed | [GitLab](/docs/guide/gitlab) |
| Azure DevOps Services or Server | [Azure DevOps](/docs/guide/azure-devops) |
| Bitbucket Cloud or Data Center | [Bitbucket](/docs/guide/bitbucket) |
| Gitea, Forgejo, or Codeberg | [Gitea-compatible hosts](/docs/guide/gitea-forgejo-codeberg) |

Use [local review](/docs/guide/local-runs) to test a config without publishing comments.

## Build your review policy

Choose the smallest authoring surface that fits the job.

| Goal | Start with |
| --- | --- |
| General pull request review | [`pipr.review(...)`](/docs/guide/quickstart) |
| Focused security, quality, or briefing workflow | [Recipes](/docs/recipes) |
| Models, paths, limits, and checks | [Configuration](/docs/guide/configuration) |
| Custom agents and task orchestration | [Custom tasks](/docs/guide/custom-tasks) |
| Exact commands, flags, and types | [Reference](/docs/reference) |

Pipr keeps config and model output away from direct code-host writes. Read [How Pipr works](/docs/concepts) for the execution model and [Trust and security](/docs/concepts/trust-security) before reviewing untrusted contributions.
