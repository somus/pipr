---
title: "How Pipr works"
description: "The concepts behind Pipr review tasks, changed-code context, agents, and publication."
---

Pipr turns a change request into validated review output. Your TypeScript config chooses when work runs and what agents review; Pipr controls diff construction and publication.

## Review flow

Every run follows the same path:

```text
Entrypoint
  -> Review task
  -> Diff Manifest
  -> Pi agent
  -> Validated output
  -> Code-host publication
```

| Concept | Purpose |
| --- | --- |
| Entrypoint | Starts work from a change request, an `@pipr` command, or local review. |
| Review task | Selects context, runs agents, and emits one final result. |
| Diff Manifest | Describes changed files and valid inline-comment ranges. |
| Agent | Runs typed instructions and read-only tools through Pi. |
| Review output | Contains a main comment, inline findings, command response, or check result. |

Use `pipr.review(...)` for a normal review. Use `pipr.task(...)` when you need custom orchestration.

## Runtime boundaries

Hosted runs load executable policy from the base branch, then review the proposed head. Agents can inspect a read-only workspace, but they do not receive direct comment or status APIs. Pipr validates task output, rejects stale results, and publishes through the selected code host.
