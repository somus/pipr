Recipes are editable starter configs generated by `pipr init`. Each recipe page shows the complete files written by the CLI.

```bash
pipr init --recipe security-sast
pipr check
```

Omit `--recipe` for the default review.

## Common setup

`pipr init` writes the config, local type support, lockfile, and selected delivery workflow. Use `--minimal` for one config file without a local install:

```bash
pipr init --recipe security-sast --minimal
npm install -D @usepipr/sdk
```

Tune the generated config before enabling automatic review:

- Change the model provider and `apiKey` secret name before committing the config.
- Run `pipr inspect` after edits to confirm models, tasks, commands, and tools.
- Use `--adapters none` when you want only the `.pipr` config files.
- Run `pipr review --base <ref>` before publishing.

## Tune review noise

| Need | Change |
| --- | --- |
| Fewer inline comments | Lower `publication.maxInlineComments` or switch to a main-comment recipe. |
| Narrower review scope | Add `paths.include` and `paths.exclude` to the recipe config. |
| More actionable findings | Make instructions require impact, evidence, and a valid changed-code range. |
| Less style feedback | Say which categories are out of scope instead of asking for a broad review. |
| Manual-only review | Use a command recipe or remove change request entrypoints. |
